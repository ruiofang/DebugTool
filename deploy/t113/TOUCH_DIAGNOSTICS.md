# T113 触摸未恢复：2026-09-18 实机诊断

用户报告界面可显示，但点击触摸屏无响应。当前尚未修复，不应把成功打开输入
设备或渲染界面当作真实触摸验收通过。

## 实测

- 屏幕实际输出为 720×1280，显示控制器将 800×1280 framebuffer 缩放到屏幕。
  用户确认是 5 寸屏；触摸驱动坐标范围 720×1280 与实际面板一致。
- 触摸设备 `fts_ts`，I2C `1-0038`，FT8756，固件版本 `0x1f`，
  FocalTech V4.2 20240407；输入节点 `/dev/input/event3`。
- udev 已标记 `ID_INPUT_TOUCHSCREEN=1`，Qt 已打开 event3。
- 用户点击期间初始 IRQ 148 计数为 0，evdev 采集文件为 0 字节。
- 驱动复位后 IRQ 计数增加到 2，但用户再次点击时未继续增加，仍无 evdev 事件。
- 芯片寄存器可读到触点数和坐标，随后完整数据帧长时间停留在旧内容。
- 向现有 evdev 注入一次明确的测试点击，事件能读回；framebuffer 截图确认
  界面切换到了 SSH 标签。该结果只验证 Qt 输入链路，不代表真实触摸恢复。

## 已尝试和恢复

执行过一次控制器复位、IRQ 关闭再启用、当前触摸驱动解绑再绑定。
重新初始化时驱动检查到控制器与内置固件版本同为 `0x1f`，升级标志为 0。
没有刷写新固件、修改设备树或重启整机。

临时尝试了 sysfs 及直接 I2C 只读轮询，再上报现有 evdev。用户验证均未恢复操作，
因此轮询已停止且未安装为服务。远端实验脚本保留为
`/mnt/UDISK/qt5com/touch_poll.experimental.py`，不能作为已验证的修复使用。
驱动 IRQ 已恢复启用（`irq_depth:0`），日志等级恢复 1。
`qt5com.service` 和 SSH 保持运行。

需要继续确认该屏幕是否曾在原厂系统正常触摸，并取得匹配这块屏幕的原厂 SDK/
内核源码及配置，才能进一步区分控制器初始化、IRQ 驱动和硬件连接问题。
